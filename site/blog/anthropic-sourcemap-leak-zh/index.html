Anthropic 级 source map 泄漏为何会发生，以及 packfence 如何拦住

2026-10-12 · 安检台笔记 · English

Also: English version

2026 年 3 月，@anthropic-ai/claude-code v2.1.88 把带非空 sourcesContent 的 .js.map 发进了 npm。 大约五十万行 TypeScript 随之暴露——不是因为什么高明的外泄工具， 而是因为 npm pack 把作者本不打算带走的文件打进了 tarball。

行李箱上了传送带，X 光机没开。这正是 packfence 要拦住的故障模式。

BAY A · 真正出了什么问题

现代 TypeScript / 打包流水线会在编译产物旁生成 source map。 很多 map 会把原始源码嵌进 sourcesContent，方便浏览器在没有单独 .ts 文件时也能显示可读堆栈。这对本地调试没问题， 对公共 registry 则不行。

npm 的打包规则很容易看走眼：

  • 写了 package.json#files 时，只有匹配路径会进包（外加始终包含的文件）。
  • 依赖 .npmignore / .gitignore 时，很容易漏掉 *.map。
  • npm pack --dry-run 能显示真相——但前提是每次发布前有人记得跑。

Anthropic 级泄漏并不玄乎：一个 map + 非空 sourcesContent + 一次没检查 tarball 的发布。 现有 pack 检查工具多半偏白名单/体积，或者很少真正进 CI。

BAY B · 真实的 npm pack 语义

packfence 不猜文件列表，而是直接调用：

npm pack --dry-run --json --ignore-scripts

这与 npm publish 使用的 npm-packlist 路径一致。 会进 tarball 的文件才会被扫描——包括 files、.npmignore、 bundled dependencies 等（dry-run 时忽略 scripts 仅为安全）。

CLEAR：这只即将起飞的包里没有默认 HOLD 项。 HOLD：拒绝发布（exit 1），直到你 allowlist 或删掉该文件。

BAY C · 默认 HOLD 规则

开箱即用，下列情况会把已打包路径标为 HOLD：

  • HOLD*.map / *.js.map / *.css.map / *.ts.map（及其他 *.map）
  • HOLDJSON 中带非空 sourcesContent 的 source map
  • HOLD.env、*.pem、*.key、id_rsa*、.git/、node_modules/
  • HOLD.npmrc（常含 _auth / _authToken）
  • HOLD内容启发式：AWS key id、PEM 私钥头、GitHub / npm / Slack 样式 token
  • HOLD单文件 > 20MB
  • WARN单文件 > 5MB · 解压总大小 > 50MB

可通过 package.json#packfence 或 .packfencerc.json （allow / deny / severity）覆盖。 故意发布的 map 可以放行；误打进去的会留在传送带上，挂上红色 HOLD。

BAY D · CLI 用法

# 尚未上架 npm registry 时从 GitHub 安装
npx --yes github:Blackman99/packfence

# 安装后
packfence .                  # 人类可读报告；HOLD 时 exit 1
packfence . --format json
packfence . --test           # 只报告不失败
packfence . --list           # 同时列出全部打包路径

退出码：0 CLEAR（或 --test），1 HOLD， 2 用法错误 / npm pack 失败。支持 human、json、github-annotations、step summary。

BAY E · GitHub Action

把安检挂进发布流水线，避免「忘了跑 dry-run」：

- uses: Blackman99/packfence@v0.2.0
  with:
    path: .
    fail: true

fail: true（默认）会在 HOLD 时让 job 失败。 放在 npm publish / OIDC 发布步骤之前即可。

BAY F · 目标线

见 GOAL.md： 在发布前告诉你，真实的 npm tarball 会不会带走 source map、密钥或其它你本不打算包含的文件——如果会，就让 CI 失败。

暂不在范围：替你改写 files（路线图 v0.3 的 packfence init）、 扫描 registry 历史、SBOM、依赖 CVE。安检台只看这一只箱子、这一条传送带、这一班航班。
