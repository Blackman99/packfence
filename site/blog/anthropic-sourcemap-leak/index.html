Why Anthropic-class source-map leaks happen — and how packfence fences them

2026-10-12 · operator console note · 中文版

Also: Anthropic 级 source map 泄漏（中文）

In March 2026, @anthropic-ai/claude-code v2.1.88 published a .js.map whose JSON carried non-empty sourcesContent. That one file exposed on the order of half a million lines of TypeScript — not because someone ran a exotic exfil tool, but because npm pack happily included a file the authors did not mean to ship.

The suitcase left the belt. The X-ray never ran. That is the failure mode packfence exists to catch.

BAY A · What actually went wrong

Modern TypeScript / bundler pipelines emit source maps next to compiled JS. Many maps embed the original sources under sourcesContent so browsers can show readable stacks without fetching separate .ts files. That is fine for local debugging. It is not fine on the public registry.

npm’s packing rules are easy to misread:

  • If you set package.json#files, only matching paths are packed (plus always-included files).
  • If you rely on .npmignore / .gitignore, omissions are easy to miss for *.map.
  • npm pack --dry-run shows the truth — but only when someone remembers to run it before every publish.

Anthropic-class leaks are not exotic. They are a map file + non-empty sourcesContent + a publish that never inspected the tarball. Existing “pack linters” are often allowlist/size focused, or barely used in CI.

BAY B · Real npm pack semantics

packfence does not guess the file list. It shells out to: 

npm pack --dry-run --json --ignore-scripts

That is the same npm-packlist path npm publish uses. Whatever would enter the tarball is what gets scanned — files, .npmignore, bundled dependencies, lifecycle quirks included (scripts ignored only for the dry-run safety).

CLEAR means: the exact bag that would fly is empty of default HOLD items. HOLD means: refuse publish (exit 1) until you allowlist or remove the file.

BAY C · Default HOLD rules

Out of the box, these put a packed path on HOLD:

  • HOLD*.map / *.js.map / *.css.map / *.ts.map (and other *.map)
  • HOLDSource maps whose JSON has non-empty sourcesContent
  • HOLD.env, *.pem, *.key, id_rsa*, .git/, node_modules/
  • HOLD.npmrc (often carries _auth / _authToken)
  • HOLDContent heuristics: AWS key ids, PEM private-key headers, GitHub / npm / Slack-looking tokens
  • HOLDIndividual file > 20MB
  • WARNFile > 5MB · total unpacked > 50MB

Override via package.json#packfence or .packfencerc.json (allow / deny / severity). Intentional maps can be allowlisted; accidental ones stay on the belt with a red HOLD tag.

BAY D · CLI usage

# from GitHub until the package is on the npm registry
npx --yes github:Blackman99/packfence

# or after install
packfence .                  # human report; exit 1 on HOLD
packfence . --format json
packfence . --test           # report without failing
packfence . --list           # also print every packed path

Exit codes: 0 CLEAR (or --test), 1 HOLD, 2 usage / npm pack failure. Formats include human, json, github-annotations, and step summary.

BAY E · GitHub Action

Fence the publish job so “I forgot to run dry-run” cannot ship:

- uses: Blackman99/packfence@v0.1.0
  with:
    path: .
    fail: true

Set fail: true (default) to exit non-zero on HOLD findings. Pair it with your release workflow before npm publish / OIDC publish steps.

BAY F · Goal line

From GOAL.md: Tell you, before you publish, whether the exact npm tarball would ship source maps, secrets, or other files you did not mean to include — and fail CI if it would.

Not in scope (yet): rewriting your files field for you (packfence init is roadmap v0.3), scanning registry history, SBOM, or dependency CVEs. The operator console watches this bag, this belt, this flight.
