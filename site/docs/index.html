CLI

packfence [path] [--format human|json|github-annotations|summary|sarif]
          [--sarif file] [--output file] [--workspaces]
          [--config file] [--list] [--test] [--fail|--no-fail]
FlagMeaning
--formatOutput style. Default human. sarif prints SARIF 2.1.0.
--sarif <file>Also write a SARIF 2.1.0 report to a file, whatever --format is.
--output, -oWrite the --format report to a file instead of stdout.
--workspaces, -wScan every publishable npm / Yarn workspace package under path.
--configPath to JSON config, relative to path (else .packfencerc.json / package.json#packfence).

--testReport HOLD findings but exit 0.

Report paths (annotations, SARIF, --workspaces bag headers) are relative to the directory you run from, so run from the repo root.

packfence init — suggest a files allowlist

packfence init [path] [--write] [--format human|json] [--config file]

Reads what npm pack --dry-run ships today and proposes a package.json files allowlist: top-level entries that main, module, types, exports, bin, browser, man or an install script point at are kept; tests, fixtures, coverage, examples, docs, CI and editor config, tool configs and src/ (when a built directory ships) are dropped; HOLD files inside a kept directory are fenced out with a negation such as !dist/**/*.map. Files npm always adds (package.json, README, LICENSE) are left out of the list. Negations you already have are kept.

The proposal is then packed for real in a scratch copy, so the after line (files, size, HOLD/CLEAR) is what npm would actually ship. --write saves it, keeping indentation and key order, and refuses if an entry point would stop shipping. Exit 0 when the proposal is CLEAR, 1 when a HOLD survives (for example a secret inside the main file, which npm always packs), 2 on errors. init works on one package at a time; pass a workspace package path for monorepos.

Exit codes

CodeMeaning
0CLEAR, or --test
1HOLD (fail-severity finding in any scanned package)
2Usage / runtime error (e.g. npm pack failed, unknown flag)

Rules

Every rule id can be re-graded in severity (fail · warn · info · allow). Content rules report file:line:col and a redacted preview such as AKIA…MPLE; the full secret is never printed or written to SARIF.

RuleDefaultWhat it catches
source-mapHOLDA *.map file would be published with the package.
sources-contentHOLDA published source map carries non-empty sourcesContent, so the original source code would ship (the Claude Code v2.1.88 failure mode).
secret-envHOLDA .env / .env.* file would be published.
secret-keyfileHOLDA *.pem, *.key, id_rsa*, *.p12 or *.pfx file would be published.
secret-npmrcHOLDAn .npmrc would be published; these often hold registry auth tokens.
npmrc-authHOLDThe published .npmrc contains _auth / _authToken.
git-dirHOLDRepository metadata under .git/ would be published.
node-modulesHOLDA node_modules/ directory would be published (outside bundleDependencies).
deny-globHOLDA packed file matches one of your deny globs.
file-too-largeHOLDA single packed file exceeds maxFileBytes (default 20 MB).
file-largeWARNA single packed file exceeds maxFileWarnBytes (default 5 MB).
total-largeWARNTotal unpacked size exceeds maxTotalBytes (default 50 MB).
content-aws-keyHOLDLooks like an AWS access key id. Matched by content scan of a packed text file.
content-private-keyHOLDContains a private key PEM header. Matched by content scan of a packed text file.
content-github-tokenHOLDLooks like a GitHub token. Matched by content scan of a packed text file.
content-npm-tokenHOLDLooks like an npm access token. Matched by content scan of a packed text file.
content-slack-tokenHOLDLooks like a Slack token. Matched by content scan of a packed text file.
content-slack-webhookHOLDLooks like a Slack incoming-webhook URL. Matched by content scan of a packed text file.
content-stripe-keyHOLDLooks like a live Stripe secret key. Matched by content scan of a packed text file.
content-anthropic-keyHOLDLooks like an Anthropic API key. Matched by content scan of a packed text file.
content-openai-keyHOLDLooks like an OpenAI API key. Matched by content scan of a packed text file.
content-huggingface-tokenHOLDLooks like a Hugging Face access token. Matched by content scan of a packed text file.

content-google-api-keyWARNLooks like a Google API key (often public in Firebase web config; confirm it is restricted). Matched by content scan of a packed text file.

Exact token formats are HOLD. Fuzzy heuristics are WARN so they surface without blocking: content-high-entropy needs a secret-looking name, a quoted value of 20+ chars, mixed character classes and ≥ 4 bits/char of Shannon entropy, and skips placeholders like your-api-key or ${TOKEN}.

Workspaces (monorepos)

packfence . --workspaces

Expands the root workspaces globs (npm and Yarn, array or { "packages": [...] }, !negation supported), runs npm pack --dry-run inside each package, and skips private: true packages. When the root itself is private, packfence expands its workspaces automatically, since the root can never be published.

Config layering: the root config applies to every package; a package's own allow / deny are appended and its severity and size limits override. Scanning a single package directory uses only that package's config.

JSON output with workspaces is { failed, warned, packages: [...], skipped: [...] }.

SARIF / code scanning

packfence . --format sarif -o packfence.sarif
packfence . --sarif packfence.sarif   # keep the human report on stdout

SARIF 2.1.0 with rule metadata, security-severity, repo-relative %SRCROOT% URIs, line/column for content hits and stable partialFingerprints, ready for github/codeql-action/upload-sarif.

GitHub Action

permissions:
  contents: read
  security-events: write   # only for SARIF upload
steps:
  - uses: actions/checkout@v4
  - uses: Blackman99/packfence@v0.2.0
    with:
      path: .
      config: ""
      fail: true
      workspaces: false
      sarif: packfence.sarif
      version: local
  - uses: github/codeql-action/upload-sarif@v3
    if: always()
    with:
      sarif_file: packfence.sarif
InputMeaning
pathPackage directory relative to the repo root (default .).
configConfig JSON, relative to path.
failtrue fails the step on HOLD.
workspacestrue scans every publishable workspace package.
sarifFile to write SARIF to; exposed as the sarif-file output.
versionlocal builds the action checkout; set a semver once the package is on npm.

Annotations and SARIF use repo-relative paths, so findings point at the right file even when path is a subdirectory.

Config schema

{
  "allow": ["glob"],
  "deny": ["glob"],
  "severity": { "source-map": "fail", "file-large": "warn" },
  "maxFileBytes": 20971520,
  "maxFileWarnBytes": 5242880,
  "maxTotalBytes": 52428800,
  "contentScanMaxBytes": 524288
}

Severity values: fail · warn · info · allow.

How the file list is built

packfence shells out to npm pack --dry-run --json --ignore-scripts so the file set matches what npm would put in the tarball (npm-packlist / files field / .npmignore).
