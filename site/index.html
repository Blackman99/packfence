BAY 02 · WHY

Anthropic shipped Claude Code source maps

In March 2026, @anthropic-ai/claude-code v2.1.88 published source maps with sourcesContent, exposing ~512k lines of TypeScript. Existing pack linters are allowlist/size focused or barely used. packfence runs real npm pack --dry-run semantics and fails on Anthropic-class mistakes.

BAY 03 · DEFAULT RULES

What puts a file on HOLD

  • HOLD*.map / *.js.map and maps whose JSON has non-empty sourcesContent
  • HOLD.env, *.pem, *.key, id_rsa*, .git/, node_modules/, .npmrc with _auth
  • HOLDExact token formats in packed text: AWS, GitHub (incl. fine-grained github_pat_), npm, Slack + webhooks, Stripe live, Anthropic, OpenAI, Hugging Face, GitLab, SendGrid, private-key PEM blocks. Reported as file:line:col with a redacted preview — the secret itself is never printed.
  • HOLDIndividual file > 20MB
  • WARNHigh-entropy values bound to secret / token / apiKey names · scheme://user:pass@host · Google API keys (often public in Firebase config)
  • WARNIndividual file > 5MB · total unpacked > 50MB

BAY 05 · MULTI-BAG BELT

Monorepos: every publishable package gets its own bag

--workspaces expands npm / Yarn workspaces globs (with !negation), runs the real npm pack --dry-run in each package, and skips private: true ones — npm would refuse to publish them anyway. A private workspace root is expanded automatically.

  1. BAG 1/2@acme/cli@2.1.0packages/cliHOLD · sourcesContent
  2. BAG 2/2@acme/core@1.0.0packages/coreCLEAR
  3. SKIP@acme/internalpackages/internalprivate

Root allow / deny apply to every bag; a package's own lists are appended and its limits override.

BAY 06 · CODE SCANNING

SARIF: HOLD findings land in the Security tab

permissions:
  security-events: write
steps:
  - uses: Blackman99/packfence@main  # SARIF + workspaces: main until v0.2.0
    with:
      workspaces: true
      sarif: packfence.sarif
  - uses: github/codeql-action/upload-sarif@v3
    if: always()
    with:
      sarif_file: packfence.sarif
ERROR Source map embeds original source · packfence · sources-content packages/cli/dist/cli.js.map · security severity 8.5

Or locally: packfence . --format sarif -o packfence.sarif. Paths are repo-relative, so alerts point at the right file.

BAY 07 · CONFIG

Allow / deny without rewriting the binary

{
  "packfence": {
    "allow": ["dist/**/*.map"],
    "deny": ["**/*.snap"],
    "severity": { "file-large": "fail" }
  }
}

Or put the same object in .packfencerc.json.
