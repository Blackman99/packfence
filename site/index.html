PACKFENCE — PRE-PUBLISH SCAN

operator console · npm pack semantics

Tell you, before you publish, whether the exact npm tarball would ship source maps, secrets, or other files you did not mean to include.

GitHub Docs · BAY Releases
BAY 01 · INSTALL

One command in CI or locally

npx github:Blackman99/packfence
# or after npm publish:
# npx packfence .
BAY 02 · WHY

Anthropic shipped Claude Code source maps

In March 2026, @anthropic-ai/claude-code v2.1.88 published source maps with sourcesContent, exposing ~512k lines of TypeScript. Existing pack linters are allowlist/size focused or barely used. packfence runs real npm pack --dry-run semantics and fails on Anthropic-class mistakes.

BAY 03 · DEFAULT RULES

What puts a file on HOLD

  • HOLD*.map / *.js.map and maps whose JSON has non-empty sourcesContent
  • HOLD.env, *.pem, *.key, id_rsa*, .git/, node_modules/, .npmrc with _auth
  • HOLDSecret content heuristics (AWS keys, private key headers, GitHub/npm tokens) in packed text files
  • HOLDIndividual file > 20MB
  • WARNIndividual file > 5MB · total unpacked > 50MB
BAY 04 · GITHUB ACTION

Fence the publish job

- uses: Blackman99/packfence@v0.1.0
  with:
    path: .
    fail: true
BAY 05 · CONFIG

Allow / deny without rewriting the binary

{
  "packfence": {
    "allow": ["dist/**/*.map"],
    "deny": ["**/*.snap"],
    "severity": { "file-large": "fail" }
  }
}

Or put the same object in .packfencerc.json.
